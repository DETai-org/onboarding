# Issue #21: Codex: установка приложения

## Контекст 🎓

Перед началом этого tutorial сначала открой [описание инструмента Codex](https://detai-org.github.io/Knowledge_substrate/ru/ecosystem/Tools/%F0%9F%A7%ADCodex/) в нашей базе знаний и быстро освежи контекст. 📚

Внутри экосистемы DET / DETai Codex — это не просто ещё одно приложение, а один из ключевых инструментов, через которые мы начинаем приближаться к реальному **vibe coding**: к такому способу работы, где идея, логика и интерфейс начинают собираться быстрее, живее и ближе к мышлению самого человека.

Именно через такие инструменты мы в дальнейшем можем создавать:
- интерфейсы, рабочие прототипы,
- внутренние сервисы и полезные приложения,

а значит — усиливать нашу собственную психологию, психотерапию и всю экосистему в целом.

В этом tutorial вы, по сути, впервые прикоснётесь к этому эффекту.

_Здесь есть и ещё один важный момент: OpenAI представила Codex app в феврале 2026 года, а 4 марта 2026 года выпустила версию для Windows. То есть мы работаем не с чем-то устаревшим, а буквально с очень свежим инструментом нового поколения._

Поэтому задача этого шага простая:  
**не просто установить приложение, а начать осваивать один из тех инструментов, через которые технологический слой экосистемы соединяется с нашей содержательной и терапевтической работой.**

---

## **Как установить приложение Codex на десктоп (обход ограничений Microsoft Store)**

Иногда Microsoft Store может блокировать доступ к приложениям по региональным или техническим причинам. В случае с приложением **Codex** для Windows, мы столкнулись с ограничениями на его скачивание. Но, благодаря нескольким простым шагам, мы смогли установить приложение **Codex** на компьютер, минуя Microsoft Store.

#### **Шаги для установки Codex на Windows**

1. **Получение ссылки на приложение Codex**:

   * Перейдите на сайт **[rg-adguard.net](https://store.rg-adguard.net/)**, который позволяет получить прямую ссылку для скачивания приложений из Microsoft Store.
   * Вставьте в поле ссылку на **Codex в Microsoft Store**:

     ```text
     https://apps.microsoft.com/detail/9PLM9XGG6VKS
     ```
   * Нажмите **галочку**, чтобы сгенерировать ссылку на скачивание. (СМ. 1 СКРИН)
   * Когда ссылка сгенерируется, **щелкните правой кнопкой мыши по ссылке** и выберите **«Копировать ссылку»**.

2. **Скачивание файла через команду PowerShell**:

   * Откройте **терминал в VS Code** (или **PowerShell**).
   * Вставьте в терминал команду для скачивания файла с помощью **`curl`**:

     ```powershell
     curl.exe -L "Сюда_вставьте_скопированную_ссылку" -o "C:\Users\[_ВАШ ПУТЬ_]\Downloads\OpenAI.Codex_26.325.3894.0_x64__2p2nqsd0c76g0.msix"
     ```
   * Это скачает файл в папку **Downloads**. (CМ. 2 СКРИН)

3. **Установка Codex через PowerShell**:

   * После того как файл будет скачан, в терминале в **VS Code** выполните команду для установки приложения:

     ```powershell
     Add-AppxPackage -Path "C:\Users\[_ВАШ ПУТЬ_]\Downloads\OpenAI.Codex_26.325.3894.0_x64__2p2nqsd0c76g0.msix"
     ```
   * Убедитесь, что нет ошибок и приложение установлено.

4. **Поиск и закрепление приложения Codex**:

   * После установки откройте меню **«Пуск»** на вашем компьютере.
   * Введите в поиске **Codex**, чтобы найти установленное приложение.
   * После того как оно появится в списке, **закрепите иконку** приложения в меню **«Пуск»**, чтобы иметь быстрый доступ к приложению в любой момент.

5. **Регистрация и настройка**:

   * При первом запуске приложения **Codex** необходимо будет пройти регистрацию.
   * Привяжите его к своему аккаунту **ChatGPT** или используйте **API ключ OpenAI**, если хотите использовать все возможности приложения.
   * После этого вы сможете выбрать проект и начать работу в интерфейсе **Codex**.

6. **Подключение плагинов и командных skills**:

   На этом шаге мы подключаем Codex к командному рабочему контуру: GitHub, ClickUp и общим skills DET.

   * В приложении **Codex** слева есть меню: перейдите в раздел **Plugins**.
   * Добавьте два плагина:
     * **GitHub**
     * **ClickUp**
   * Если вы уже добавлены в командные процессы DETai-org и авторизованы в нужных сервисах, плагины должны привязаться к вашим аккаунтам после подключения.

   Процесс сам всё свяжет. Главное — смотрите, чтобы авторизация и открытие браузера происходили через ваш рабочий Google / GitHub аккаунт.

   После подключения плагинов добавьте локальный репозиторий onboarding как проект в Codex, нажав **«Добавить новый проект»** или `CTRL+O`, и выберите папку:

   ```text
   D:/dev/DETai-org/onboarding
   ```

   > Перед этим у вас уже должен быть локально скачан репозиторий `DETai-org/onboarding` в папку `D:/dev/DETai-org/onboarding`. Это делается в tutorial [VS Code + GitHub — первичная настройка](https://github.com/DETai-org/onboarding/issues/7), в шаге про клонирование репозитория.

   После создания проекта внутри него можно начинать диалоги с Codex. В первом диалоге установите командные skills:

   * Откройте README с описанием командных skills:  
     [DETai-org/onboarding/.codex-skills/README.md](https://github.com/DETai-org/onboarding/blob/main/.codex-skills/README.md)
   * Перейдите в ClickUp-лист с готовыми промптами:  
     [Promt for codex](https://app.clickup.com/90152202658/v/li/901523014418)
   * Откройте задачу [**«Установка командных Codex skills с объяснением»**](https://app.clickup.com/t/86c9gt85g).
   * Скопируйте промпт из описания задачи и вставьте его в первый диалог внутри проекта onboarding в Codex.
   * См. СКРИН 3.
   * После этого советуем вам продолжить диалог в этом чате, поскольку контекст у него будет практически всей экосистемы. Спрашивайте у него любые вопросы.
  
> [!TIP]
> _Просите Codex обращаться к базе MKDocs на GitHub, ClickUp, GitHub и другим источникам. Вызывайте соответствующие плагины через `@`, указывайте конкретные ссылки или ID. Например, чтобы Codex прочитал задачу в ClickUp, укажите её ID; если нужно проанализировать целый лист, дайте ссылку на этот лист. Чтобы Codex прочитал tutorial на GitHub или материал из нашей базы знаний в MkDocs, дайте ему полный URL._

7. **Установка GitHub CLI и подготовка Pull Request-процесса**:

   На этом шаге мы устанавливаем **GitHub CLI** — официальный инструмент GitHub для работы с репозиториями из командной строки.

   Простыми словами: GitHub CLI нужен для того, чтобы Codex и ваш компьютер могли не только менять файлы локально, но и удобно создавать **Pull Request** — запрос на включение изменений в общий репозиторий.

   Это важно для командной работы. Мы не хотим, чтобы любые изменения сразу попадали в основную ветку `main`. Сначала участник делает изменения в своей ветке, затем создаёт Pull Request, а ответственный член команды проверяет эти изменения и только после этого сливает их в общий проект.

> [!NOTE]
> **Ветка** — это отдельная линия работы внутри того же проекта. Файлы у вас меняются локально в папке `onboarding` на компьютере, но изменения не попадают в основную ветку `main`, пока Pull Request не будет проверен и принят.

   #### 7.1. Откройте и закрепите PowerShell

   * Нажмите **Пуск** в Windows.
   * В поиске введите **PowerShell**.
   * Откройте **Windows PowerShell**.
   * Чтобы не искать его каждый раз, закрепите PowerShell:
     * либо на **панели задач**;
     * либо в меню **Пуск** / быстром доступе.

   #### 7.2. Установите GitHub CLI

   В открытом PowerShell введите команду:

   ```powershell
   winget install --id GitHub.cli
   ```

   Дождитесь окончания установки. В конце должно появиться сообщение вроде:

   ```text
   Успешно установлено
   ```

   #### 7.3. Перезапустите PowerShell

   После установки GitHub CLI закройте текущее окно PowerShell полностью.

   Затем снова откройте PowerShell через **Пуск**.

   Это нужно, потому что Windows часто видит новую команду `gh` только после открытия нового окна терминала.

   #### 7.4. Проверьте, что GitHub CLI установился

   В новом PowerShell введите:

   ```powershell
   gh --version
   ```

   Если всё хорошо, вы увидите версию GitHub CLI, например:

   ```text
   gh version 2.91.0
   ```

   Если PowerShell пишет, что команда `gh` не найдена, закройте PowerShell и откройте его ещё раз. Если ошибка остаётся, проверьте прямой путь:

   ```powershell
   & "C:\Program Files\GitHub CLI\gh.exe" --version
   ```

   #### 7.5. Авторизуйтесь в GitHub

   В PowerShell введите:

   ```powershell
   gh auth login
   ```

   Дальше GitHub CLI начнёт задавать вопросы. Выбор делается стрелками на клавиатуре, а подтверждение — клавишей **Enter**. Обычно выбранный пункт подсвечивается синим или выделяется стрелкой `>`.

   Выбирайте так:

   * На вопрос **`Where do you use GitHub?`** выберите:

     ```text
     GitHub.com
     ```

   * На вопрос **`What is your preferred protocol for Git operations?`** выберите:

     ```text
     HTTPS
     ```

   * На вопрос **`Authenticate Git with your GitHub credentials?`** выберите:

     ```text
     Yes
     ```

   * На вопрос о способе входа выберите:

     ```text
     Login with a web browser
     ```

   После этого PowerShell покажет одноразовый код и предложит открыть страницу GitHub в браузере. Будет примерно так:

   ```text
   First copy your one-time code: XXXX-XXXX
   Press Enter to open https://github.com/login/device in your browser...
   ```

   Скопируйте код, нажмите **Enter**, откроется браузер. На странице GitHub вставьте код и подтвердите авторизацию.

   Если GitHub покажет экран **Authorize GitHub CLI**, нажмите зелёную кнопку:

   ```text
   Authorize github
   ```

> [!TIP]
> Если на экране авторизации вы видите `Organizations and teams: Read-only`, это нормально. GitHub CLI просто получает право читать список организаций и команд, чтобы понимать, к каким репозиториям у вас есть доступ. Для работы с `DETai-org/onboarding` это ожидаемое поведение.

   После успешной авторизации в PowerShell должно появиться сообщение вроде:

   ```text
   ✓ Authentication complete.
   ✓ Logged in as ВАШ_АККАУНТ
   ```

   #### 7.6. Проверьте авторизацию

   Введите:

   ```powershell
   gh auth status
   ```

   Если всё хорошо, вы увидите, что вошли в `github.com` под своим аккаунтом. Например:

   ```text
   ✓ Logged in to github.com account your-name
   ```

   #### 7.7. Перезапустите Codex

   После установки и авторизации GitHub CLI полностью закройте приложение **Codex** и откройте его заново.

   Это нужно, чтобы Codex увидел установленную команду `gh`.

   После перезапуска кнопка **«Создать PR»** / **«Создать Pull Request»** в верхней правой части интерфейса должна стать доступной, когда вы работаете в отдельной ветке и уже подготовили изменения.

   #### 7.8. Как теперь правильно работать с изменениями

   Внизу под диалогом Codex есть переключатель ветки. Обычно сначала там стоит:

   ```text
   main
   ```

   Для обычной работы не нужно менять файлы прямо в `main`. Вместо этого:

   * нажмите на переключатель ветки внизу;
   * выберите **«Создать и переключиться на новую ветку...»**;
   * задайте понятное имя ветки, например:

     ```text
     feature/update-onboarding-tutorial
     ```

   После этого Codex и вы будете вносить изменения в этой ветке. Локально файлы будут меняться в вашей папке `D:/dev/DETai-org/onboarding`, но в основной репозиторий GitHub они попадут только после проверки.

   Общая логика такая:

   ```text
   Создать ветку → внести изменения → совершить commit → отправить ветку на GitHub → создать Pull Request → дождаться проверки → слить в main
   ```

> [!IMPORTANT]
> **Pull Request — это не финальное добавление изменений в проект.** Это запрос на проверку. Ответственный участник команды смотрит, что именно изменилось, задаёт вопросы при необходимости и только потом принимает изменения в основную ветку `main`.

   Такой процесс помогает нам централизованно контролировать качество: в общий репозиторий не должен случайно попасть сломанный код, неверная инструкция или незавершённый эксперимент.

### **Заключение**

Теперь приложение **Codex** установлено на вашем Windows-десктопе и готово к использованию. Все эти действия можно выполнить через **PowerShell** или терминал **VS Code**, что делает процесс установки достаточно простым и повторяемым.

**Важно помнить**: скачивание и установка через Microsoft Store не всегда доступны, и иногда проще воспользоваться **альтернативными методами**, как мы это сделали в данном случае, чтобы обойти региональные ограничения или проблемы с самим Store.

После подключения GitHub, ClickUp и командных skills Codex становится не просто установленным приложением, а рабочим участником вашего локального процесса: он видит проект, понимает командные правила и может помогать в общем стиле экосистемы DET.

После установки **GitHub CLI** вы также подключаете Codex к нормальному командному процессу разработки: работа идёт через ветки и Pull Request, а изменения проходят проверку перед попаданием в `main`. Это даёт команде понятный контроль качества и помогает безопасно работать нескольким участникам одновременно.

В итоге этот tutorial помогает вам:

* установить Codex на Windows даже при ограничениях Microsoft Store;
* подключить GitHub, ClickUp и командные skills DET;
* открыть локальный проект onboarding в Codex;
* установить GitHub CLI и авторизовать его;
* понять базовую логику веток, commit, push и Pull Request;
* начать работать так, чтобы изменения были видны команде и проходили проверку перед слиянием в общий репозиторий.

## Обновления приложения Codex: как это работает 

Когда приложение Codex установлено через файл .msix, обновления не происходят автоматически, как в случае с приложениями из Microsoft Store. Это означает, что если OpenAI выпустит новую версию приложения, тебе нужно будет самостоятельно проверять наличие обновлений и скачивать новые версии.

1. **Проверь страницу Codex раздел "Приложения" на ней тебя перекинет в Microsoft Store**: 

2. **Получение актуальной ссылки**: Скопируй URL этой страницы. В URL всегда будет содержаться версия приложения, и при выходе нового обновления, ссылка поменяется.

3. **Использование rg-adguard.net**: Вставь скопированную ссылку в сайт **rg-adguard.net**. Сайт сгенерирует прямую ссылку для скачивания MSIX-файла с обновлением.

4. **Скачивание и установка**: Скачай **новую версию** и установи её с помощью команд приведённых выше

 **Рекомендуется проверять обновления раз в 1-2 месяца**.
