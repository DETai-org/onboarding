# Issue #10: Obsidian (название файлов)

# Obsidian — локальная подготовка документов

Этот туториал описывает, как настроить в Obsidian корректную схему именования заметок:

**H1 → frontmatter.title → slug (имя файла).**

Задача — в архитектурной совместимости с Knowledge Base (GitHub + MkDocs).

Если документ создаётся в Obsidian, он должен быть готов к переносу в канон без ручной доработки.

---

## Архитектурный принцип

В системе действует правило:

* имя файла — это **slug в kebab-case** (для GitHub и стабильных URL),
* `frontmatter.title` — это человекочитаемое название,
* первый заголовок (H1) — смысловой источник названия.

Проблема:
Obsidian по умолчанию отображает в левом меню именно **имена файлов**, поэтому мы собираем связку, которая позволяет:
- хранить файл как `kebab-case.md`
- показывать его в меню как нормальное название (через `title`)
- быстро синхронизировать заголовки/метаданные без ручной рутины
Поэтому мы настраиваем связку из шаблона и двух плагинов, чтобы:

* файл физически хранился как `kebab-case.md`,
* в интерфейсе отображался нормальный заголовок,
* H1 и `title` синхронизировались автоматически.

---

## Зачем нужен этот туториал

Он отвечает на один конкретный вопрос:

> Если вы используете Obsidian для личной подготовки документа,
> как сделать так, чтобы он сразу соответствовал стандарту системы?


---

## 🎯 Итоговая схема (что мы получаем)

1) **Файл физически хранится в kebab-case**  
   Пример: `ecosystem-architecture.md`

2) **Внутри файла есть frontmatter** (минимум `title` и `date_ymd`)

3) **В Obsidian в левом меню и в ссылках отображается `title`**, а не slug

4) **Автоматизация**:
   - шаблон создаёт правильный frontmatter сразу
   - плагин №1 умеет показывать `title` вместо имени файла в интерфейсе
   - плагин №2 умеет подтягивать **первый заголовок** в `title` (и запускать синк командой / хоткеем)

---

## 🔩 Компоненты цепочки

### 1) Шаблон: `frontmatter_template`
Назначение: при создании новой заметки быстро вставлять правильный frontmatter.

**Содержимое шаблона:**
```yaml
---
title:
date_ymd: <% tp.date.now("YYYY-MM-DD") %>
---
````

> Важно: `date_ymd` — наш внутренний стандарт (чёткий формат YYYY-MM-DD).

---

### 2) Плагин: **Front Matter Title** (Author: _Snezhig_)

Назначение: **показывать `title` из frontmatter вместо имени файла** в Obsidian UI.

Рекомендуемые включения в настройках (по смыслу):

- **Explorer** — заменить названия в File Explorer
    
- при желании: Tabs / Header / Backlink / Search (если хочешь везде видеть title)
    

---

### 3) Плагин: **File Title Updater** (Author: wenlzhang)

Назначение: синхронизировать первый заголовок (H1) и `frontmatter.title`.

#### ✅ Обязательные настройки (только то, что мы меняли)

1) **Default title source** → `First heading`  
   Источник истины — первый заголовок в заметке.

2) **Sync mode** → `Frontmatter + Heading`  
   Плагин синхронизирует только:
   - H1  
   - `frontmatter.title`  

Имя файла (kebab-slug) мы оставляем под ручным контролем — это осознанное архитектурное решение.

Все остальные настройки можно оставить по умолчанию.

#### ⚙️ Как используем

Команда:
`File Title Updater: Sync titles using default source`

Вызываем:
- через `Ctrl + P`
- или горячей клавишей (у нас сейчас: `Alt + U`)

> Логика работы:
> 1. Пишем H1.
> 2. Нажимаем горячую клавишу.
> 3. Заголовок автоматически попадает в `frontmatter.title`.
> 4. Плагин Front Matter Title отображает его в левом меню.

---

## ✅ Рабочий процесс создания новой заметки

1. **Создай файл в папке** и сразу задай имя файла в kebab-case  
    Пример: `management-layer.md`
    
2. Вставь шаблон `frontmatter_template`  
    (через Templater / быстрый вызов шаблонов)
    
3. Напиши первый заголовок (H1) нормальным языком  
    Пример: `# Management Layer` или `# Архитектура экосистемы`
    
4. Нажми хоткей синка `File Title Updater` → заголовок подтянется`frontmatter.title`
    
5. В File Explorer будет отображаться `title`, а файл на диске останется slug’ом  
    → идеально для импорта в Knowledge Base
    

---

## ⚠️ Важные правила и оговорки

- **Slug (имя файла) — это физическое имя на диске.**  
    Оно остаётся и используется при импорте / в GitHub / в MkDocs путях.
    
- **Title — это слой отображения (UI-имя).**  
    Он нужен для читабельной навигации в Obsidian и “человеческих” заголовков.
    
- Если забыть синхронизацию — ничего не сломается, просто `title` не обновится.
- Slug остаётся основанием для сортировки структуры.
Именно kebab-имя файла используется в sortspec.md (Custom File Explorer Sorting) и определяет реальный порядок в дереве.
Title влияет только на отображение, но не на логику сортировки.

Процесс настройки сортировки и работы с sortspec.md подробно описан НИЖЕ ⬇️⬇️⬇️
    

---

## ✅ Теперь ты умеешь

- хранить структуру как в Knowledge Base (slug-first)
    
- видеть в Obsidian красивую навигацию (title-first)
    
- создавать заметки без ручного переименования и “переписывания под MkDocs”
    
- поддерживать единый стандарт для команды: **2 плагина + 1 шаблон = стабильный импорт**

# 🗂 Управляемая структура файлов в Obsidian  

## (Настройка кастомной сортировки под архитектуру DET / базы знаний)

---

## 🎯 Контекст

В нашей среде расположение файлов не случайно.

Оно привязано к:
- структуре базы знаний (Knowledge Base / MK Books),
- единой логике навигации,
- одинаковому порядку разделов во всех инструментах.

Это значит:

> Структура должна быть привычной и одинаковой везде.

Однако Obsidian по умолчанию сортирует файлы:
- по алфавиту,
- по дате,
- или по стандартной логике.

Он **не позволяет вручную задать архитектурный порядок разделов**.

Поэтому мы используем специальный плагин.

---

# 🚀 Задача

Настроить Obsidian так, чтобы:

- папки отображались в архитектурном порядке (как в базе знаний),
- порядок был управляемым,
- можно было управлять вложенными папками,
- не использовать числовые костыли `01_`, `02_` и т.п.

---

# 🔌 Шаг 1. Установка плагина

### 1. Открыть настройки Obsidian
`Settings → Community plugins`

### 2. Включить Community Plugins
Если отключены — нажать кнопку включения.

### 3. Нажать **Browse**

### 4. Найти плагин:

```

Custom File Explorer sorting

```

Автор: SebastianMC

### 5. Нажать:
- Install
- Enable

После этого в контекстном меню появится пункт `Custom sort`.

---

# 🗂 Шаг 2. Создание служебной папки для конфигурации

Мы рекомендуем хранить технические файлы отдельно.

Если в vault нет папки для конфигурации — создайте её.

Например: _config Или: 11_core_scripts (как в нашем примере)

---

# 📄 Шаг 3. Создание файла сортировки

Создаём файл:

```
sortspec.md

```


# ⚙️ Шаг 4. Указание пути к конфигурации

Перейдите в: `Settings → Custom File Explorer sorting`

Найдите поле:

```
Path or name of additional note(s) containing sorting specification
```

И укажите относительный путь:

```
11_core_scripts/sortspec
````

(без `.md`)

---

# 🧠 Шаг 5. Правильный синтаксис (ВАЖНО)

Плагин НЕ использует YAML-списки.

Он читает строки внутри `sorting-spec` как текст.

Правильный формат:

```yaml
---
sorting-spec: |
  target-folder: /

  Ecosystem


  target-folder: Ecosystem

  DET
  DETai
---

````

Дальше вложенность папок прописывается вот так и если нужно сортировка файлов то расширение не прописываем то есть без `.md`

Пример:

```yaml
  target-folder: Ecosystem/Governance

  Constitution
  index
````

---

## ❗ Важно помнить

* НЕ использовать `-` перед пунктами, НЕ писать `.:`, НЕ добавлять лишние отступы
* `target-folder: /` — это корень vault
* `target-folder: Ecosystem` — это конкретная папка
* НЕ ставить `/Ecosystem` (со слешем в начале)
* Названия должны совпадать **символ в символ**

---

# ▶ Шаг 6. Применение сортировки

1. Сохраните файл.
2. В File Explorer:

   * ПКМ по пустому месту
   * `Custom sort → Apply custom sorting`

Или ПКМ по конкретной папке → Apply.

---

# 🧩 Что происходит дальше

Плагин:

1. Читает `sortspec.md`
2. Находит блок `target-folder`
3. Применяет порядок
4. Всё, что не указано — размещает ниже в стандартной сортировке

---

# 🏗 Рекомендованная практика

* Храните все технические конфигурации в отдельной папке `_config` или `core_scripts`
* Не используйте числовые префиксы для управления порядком
* Управляйте структурой декларативно через `sortspec.md`

---

# ✅ Результат

Теперь вы умеете:

* Управлять порядком папок архитектурно
* Настраивать сортировку вложенных уровней
* Делать структуру Obsidian идентичной базе знаний
* Избегать числовых костылей
* Понимать, как работает `target-folder`
